# يد تحكم افتراضية لنينتندو سوتش (Android)

مشروع Android Studio (Kotlin) يحوّل الهاتف إلى يد تحكم (Gamepad) تتصل
بجهاز Nintendo Switch مباشرة عبر بروفايل **Bluetooth HID Device**.

## المتطلبات
- Android Studio (أحدث إصدار).
- هاتف يعمل بـ Android 9 (Pie) أو أعلى، ويدعم **Bluetooth HID Device profile**
  (ليس كل الهواتف تدعمه فعليًا حتى لو كانت النسخة مناسبة — جرّب على جهازك أولًا).
- بعض إصدارات فيرموير السوتش الحديثة قد تحتاج الهاتف يكون **rooted (Magisk)**
  حتى يقبل الإقران بثبات.

## كيف يعمل المشروع
1. `GamepadDescriptor.kt` يحدد شكل بيانات الجويباد (16 زر + D-Pad + عصاتين) بصيغة HID قياسية.
2. `HidGamepadManager.kt` يسجّل التطبيق كجهاز HID عبر `BluetoothHidDevice` API،
   ويرسل تقرير (Report) جديد في كل مرة يتغيّر فيها زر أو عصا.
3. `MainActivity.kt` يبني واجهة الأزرار (D-Pad, A/B/X/Y, L/R, ZL/ZR, +/-, Home, Capture)
   ويربطها بالمدير أعلاه.

## خطوات التجربة على جهاز حقيقي
1. افتح المشروع في Android Studio ونصّبه على الهاتف.
2. فعّل البلوتوث على الهاتف وامنح التطبيق صلاحياته عند الطلب.
3. على السوتش: من القائمة الرئيسية → أيقونة **"Controllers"** → **"Change Grip/Order"**
   (تغيير المسكة/الترتيب) — هذا يضع السوتش في وضع البحث عن يد تحكم جديدة.
4. افتح التطبيق على الهاتف وانتظر ظهور اسم "Switch Virtual Gamepad" في قائمة
   الأجهزة على شاشة السوتش، ثم اختره.
5. إذا تم الإقران بنجاح، ستتحول شاشة التطبيق للتحكم الفعلي بالسوتش.

## حدود معروفة (مهم تعرفها قبل ما تعتمد عليه)
- هذا وصف HID **عام** (Generic Gamepad) وليس نسخة طبق الأصل من بروتوكول
  الجويكون الحقيقي (الذي يستخدم أوامر UART مخصصة موثقة في مشروع
  [dekuNukem/Nintendo_Switch_Reverse_Engineering](https://github.com/dekuNukem/Nintendo_Switch_Reverse_Engineering)).
  قد يقبل السوتش هذا الوصف كـ"يد تحكم عامة" أو قد يرفضه حسب إصدار الفيرموير.
- لا يوجد حاليًا دعم لموتور الاهتزاز (Rumble) أو الحساسات الحركية (Motion/Gyro)
  أو كاميرا IR.
- الاتصال أقل ثباتًا من يد تحكم أصلية (تأخير أو انقطاع أحيانًا) — هذا متوقع
  مع أي محاكاة HID عبر تطبيق.
- إذا واجهت رفض بالإقران بشكل متكرر، الخيار الأضمن تقنيًا هو استخدام تطبيق
  **JoyCon Droid** الجاهز والمفتوح المصدر كمرجع للمقارنة أو كبديل جاهز،
  لأنه مرّ بمراحل تجربة وتصحيح طويلة مع إصدارات فيرموير مختلفة.

## تطوير لاحق مقترح
- إضافة عصا تحكم تناظرية حقيقية (Draggable Joystick View) بدل الأزرار الثابتة.
- تجربة قيم `subclass` مختلفة في `BluetoothHidDeviceAppSdpSettings` إذا لم
  يتعرف عليه السوتش من أول مرة.
- إضافة زر "إعادة تسجيل" (Re-register) في حال فشل `registerApp`.
